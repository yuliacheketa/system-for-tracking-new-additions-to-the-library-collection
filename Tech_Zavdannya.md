# Технічне завдання (спрощене)

**Проєкт:** System for Tracking New Additions to the Library Collection  
**Повна назва:** система обліку нових надходжень до бібліотечного фонду  
**Версія документа:** 1.0  

Документ складено на початку робіт (як у класичних моделях ЖЦ: Waterfall / V-модель) і фіксує, що саме має бути зроблено в першій версії системи.

---

## 1. Мета і завдання продукту

**Мета.** Створити веб-систему, у якій бібліотека може фіксувати нові книги та матеріали в одному місці — від моменту надходження до появи в каталозі та показу читачам.

**Завдання продукту:**
1. Дати змогу реєструвати нові надходження (закупівлі, дари).
2. Вести статуси обробки запису (отримано, в обробці, каталогізовано, готово до видачі).
3. Дозволяти / уточнювати каталожні дані без дублювання карток.
4. Показувати читачам (гостям) публічний список новинок.
5. Розрізняти права доступу за ролями (адміністратор, бібліотекар, закупівля, каталогізатор, гість).

---

## 2. Загальні функціональні вимоги

1. Додавання нового надходження з базовими полями: назва, автор, рік, тип (закупівля / дар), дата отримання.
2. Зміна статусу обробки користувачем з відповідною роллю.
3. Редагування бібліографічних / каталожних даних уже створеного запису.
4. Перегляд публічного списку нових надходжень без права редагування (гість).
5. Керування користувачами та ролями адміністратором (створення, призначення ролі, блокування).

Детальніший перелік вимог наведено у файлі `requirements/requirements.md`.

---

## 3. Загальні нефункціональні вимоги

1. Інтерфейс має бути зрозумілим для працівників бібліотеки: основні дії видно без довгого навчання.
2. Доступ до функцій обмежений ролями; гість не редагує записи.
3. Базові сторінки (список, форма додавання) мають відкриватися за прийнятний час (орієнтовно до 2–3 с при звичайному навантаженні).
4. Після успішного збереження дані не губляться при повторному вході.
5. Коректна робота в актуальних версіях Chrome і Firefox (десктоп). Мобільна версія — не пріоритет першої поставки.

---

## 4. Обмеження

1. Перша версія орієнтована на одну бібліотеку / один фонд, без інтеграції з зовнішніми бібліотечними системами.
2. Не передбачено повноцінний модуль видачі книг читачам (абонемент) — лише облік нових надходжень і підготовка до каталогу.
3. Мобільний клієнт і складні звіти / аналітика виходять за межі цього ТЗ.
4. Склад вимог на етапі ТЗ вважається фіксованим для першої ітерації; суттєві зміни оформлюються окремо (підхід класичних моделей ЖЦ).
5. Підтримуються основні сучасні десктоп-браузери (Chrome, Firefox); інші середовища — за можливості.

---

## 5. Очікувані результати

1. Працююча веб-система обліку нових надходжень з ролями користувачів.
2. Можливість пройти типовий шлях: реєстрація надходження → зміна статусів → каталогізація → поява в списку новинок.
3. Набір базової документації: вимоги, user stories, use case діаграма, це ТЗ.
4. Результат, який можна перевірити за пунктами цього документа (відповідність заявленим функціям і обмеженням).
